# OpenWhispr の推論サービス

Windows の OpenWhispr から、専用 Tailscale Service 経由で文字起こしと整形を利用します。
録音・ホットキー・貼り付けはクライアントが担当します。
推論ホストは Whisper Large v3 Q5_0 と Gemma 4 E4B を起動時に読み込み、アイドル時も保持します。

## 適用前の確認

モデルの取得元と SHA-256 は `hosts/jupiter/openwhispr.nix` で宣言します。
切り替え前に、Windows で選択中の実ファイルの SHA-256 と一致することを確認してください。
同じ表示名でも、QAT 版や再配布されたファイルとは区別します。
モデルはクライアントと同一の重みを保つため、自動更新の対象にしません。
推論エンジンは通常の Nixpkgs 更新に従います。

一致する公開版がない場合は、Windows の原本を import 用領域へコピーします。
原本の SHA-256 をモデル定義の `sha256` と import ファイル名の両方へ設定し、URL をそのファイルの `file://` URL に変更します。
import 用領域は `/var/lib/openwhispr-model-import/`、ファイル名は期待する SHA-256 とします。
領域は root 所有・モード 0700 とし、原本を完成世代へ直接配置しないでください。
再インストール時には、Nix の適用前に Windows の原本から同じ import 元を復元します。

Tailscale 管理用リポジトリーの `services.json` で `svc:openwhispr` の TCP 443 を登録します。
Nix の適用でホストから広告した後、そのリポジトリーの承認スクリプトでホストを承認します。
承認後も専用 HTTPS に接続できない場合は、公開サービスを再起動して再広告します。

```console
sudo systemctl restart openwhispr-serve
```

ホスト共用の HTTPS エンドポイントや Funnel は使用しません。

## 起動と状態確認

`openwhispr-models` がモデルの取得・SHA-256 照合を行います。
ディスクへの書き出しを完了してから、2 モデルを完成世代として一括配置します。
完成世代は `/var/lib/openwhispr-models/` に保持し、推論ユーザーには読み取りだけを許可します。
モデル本体は Nix のシステム依存と公開バイナリキャッシュに含めません。
初回取得には配布元への接続、または事前の原本 import が必要です。
完成世代がある通常の再起動では、モデルを取得し直しません。

```console
sudo systemctl status openwhispr-models openwhispr-whisper openwhispr-cleanup openwhispr-serve
sudo journalctl -u openwhispr-models -u openwhispr-whisper -u openwhispr-cleanup -b
```

取得は暫定で最大 2 時間、推論サーバーの準備完了待ちは最大 10 分です。
推論サーバーの起動上限は 11 分とし、準備待ちを先に打ち切らないようにします。
初回配備では転送・検証・モデルの読み込みが終わるまで利用できず、設定適用のコマンドもその完了を待ちます。
モデル定義を更新する場合も、その間は Windows のローカル構成を利用してください。

```console
curl --fail http://127.0.0.1:8178/health
curl --fail http://127.0.0.1:8179/health
```

両 API が HTTP 200 と `{"status":"ok"}` を返すことを確認します。
文字起こしと整形は別々に再起動でき、公開設定はその再起動に連動して削除しません。

## Windows の接続と切り替え

Service の登録・承認後に、Windows から到達する専用 HTTPS の完全修飾ドメイン名を確認します。
Transcription の Self-Hosted URL は専用 URL の末尾に `/stt/v1` を付け、モデル欄を `large-q5` にします。
Dictation Cleanup の Self-Hosted URL は末尾を `/llm/v1` とし、モデル欄を `gemma-4-e4b` にします。
アプリがそれぞれ `/audio/transcriptions` と `/chat/completions` を追加します。

切り替え前にローカル設定を控え、短い日本語と辞書語・固有名詞を含む長めの発話で出力と所要時間を記録します。
専用 URL への直接の API 確認後、通常のホットキーで録音から貼り付けまで確認してください。
言語の自動判定・固定指定、辞書、整形指示を維持し、初回・連続利用・間を空けた後を比較します。
接続テストだけでは、文字起こし・整形・貼り付けの確認には代えられません。
両モデルの同時稼働時に、起動ログで Radeon の Vulkan 利用も確認します。
コンテキストの初期値は 8192 です。実際の指示・入力・出力上限が収まることを確認し、不足すれば Nix の定義を変更します。

ホストと Tailscale の再起動後も追加の接続操作なく入力できることを確認します。
最後に両設定を控えたローカル構成へ戻し、Windows 単体でも入力できることを確認してください。
すべての確認に合格した場合は両設定を Self-Hosted に戻して利用し、不合格の場合は両設定をローカル構成のままにします。
ホスト停止・ネットワーク切断時の自動フォールバックはありません。
その場合は文字起こしと整形の両設定をローカル構成へ戻します。Windows のモデル原本は削除しません。

## 取得失敗と切り戻し

通信の一時失敗は自動で再試行します。
SHA-256 不一致やローカル原本の欠落は終了コード 65 で停止し、同じファイルを繰り返し取得しません。
ログの取得元・期待ハッシュ・実測ハッシュを照合し、正しい原本を復元するか、原本と照合した Nix の宣言を訂正してから再開します。
Nix の宣言を変更した場合は、リポジトリールートから設定を再適用します。

```console
nh os switch
```

破損したコピーに期待ハッシュを合わせないでください。

原本のファイルだけを復元し、宣言を変更していない場合は準備サービスを再起動します。

```console
sudo systemctl restart openwhispr-models
```

準備に成功すると両推論サービスも起動します。
失敗した取得は旧完成世代を変更しません。
モデル定義を含む以前の NixOS 世代へ戻すと、その世代に対応する保存済みモデルを再利用します。
切り戻しに備え、必要な NixOS 世代とモデル世代を一緒に保持してください。
